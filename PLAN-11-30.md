# Days 11 to 30: a discovery exercise

James stopped prompting after day 10: the engagement on this format had dropped. From day 11 Claude sets its own brief each day. The point changes from showing to finding out: what can code design actually do, and how far can it go with the tools in this session, while still looking made by a person who cares, not by a machine.

Each poster takes one graphic design or art principle and one technique it hasn't used yet. No two days share either. Every one has to pass the phone check (`scripts/feed-check.py`): one big idea that reads at 130 px, detail only as texture.

How each day is made, every day:
1. Write the brief (`prompt.md`, marked as Claude's own in `meta.json` with `"author": "claude"`, so the site never passes it off as James's).
2. Build it, render it, look at it at full size and at phone size.
3. Review loop, until nothing is left to fix: as a graphic designer (hierarchy, grid, type), as an artist (is there an idea, does it move you), as an illustrator or image maker (craft, texture, does anything look generated), as a creative director (does it say one thing, does it read on a phone). The `design-critique` skill's framework (first impression, usability, hierarchy, consistency) runs on each.
4. Keep the development log in `dev/` as on every other day, so socials can still be made later (`build-day.sh` needs only the copy written).

No money is spent without James. Day 28 uses Figma's image model on AI credits he approved.
